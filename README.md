# 概要

社内の備品（PC・工具・計測器等）の貸出申請・承認・貸出・返却・履歴管理を行うWebアプリケーション。

- 一般利用者：備品の検索・予約状況確認・貸出申請・自分の申請状況確認・通知確認ができる。
- 管理者：一般利用者の操作に加えて、申請の承認・却下、貸出・返却処理、申請の取消、備品登録・編集・無効化（CSV一括登録を含む）、ユーザー登録・編集・無効化、貸出履歴の閲覧・CSV出力ができる。

### 構成

- フロントエンド：`frontend/`（React / TypeScript / Vite、Nginx配信）
- バックエンド：`backend/`（Python / FastAPI / SQLAlchemy / PostgreSQL）
- 設計書・開発プロセス成果物：`要件定義書/`・`設計書/`・`作業管理/`・`引継ぎ資料/`・`テスト仕様書/`・`レビュー指摘表/`

# セットアップ（必要なら）

1. 環境変数を設定する（`.env`はGitに含めないため、各自のローカルで作成する）。

   | 変数名 | 内容 |
   |---|---|
   | `POSTGRES_USER` | PostgreSQLユーザー名 |
   | `POSTGRES_PASSWORD` | PostgreSQLパスワード |
   | `POSTGRES_DB` | PostgreSQLデータベース名 |
   | `JWT_SECRET_KEY` | アクセストークン署名用の秘密鍵 |
   | `ADMIN_USER_ID` | 初期管理者ユーザーID（3〜32文字） |
   | `ADMIN_NAME` | 初期管理者氏名 |
   | `ADMIN_PASSWORD` | 初期管理者初期パスワード（8文字以上。初回ログイン時に変更が必須） |

2. 起動する。

   ```
   docker compose up --build
   ```

3. 初回アクセス時は、`ADMIN_USER_ID`／`ADMIN_PASSWORD`でログインし、案内に従ってパスワードを変更する。以降の管理者アカウントは、ログイン後の「ユーザー管理」画面で既存の管理者が作成する。

# 使用方法

### 一般利用者

1. ログイン画面でユーザーID・パスワードを入力してログインする。初回ログイン時はパスワード変更が必須。
2. ホーム画面で、自分宛の通知（承認・却下・取消の結果、返却期限が近い・超過している貸出）を確認する。
3. 「備品一覧」画面で、分類・キーワード・状態（貸出可／貸出中）で備品を検索する。
4. 検索結果から備品を選び「備品詳細」画面を開く。承認済み・貸出中の期間（予約状況）を確認し、空いている期間で貸出期間（開始日・返却予定日）と用途を指定して貸出を申請する。将来日の予約も申請可能。
5. 「自分の申請一覧」画面で、自分の申請の状態（申請中・承認済み・貸出中・返却済み・却下・取消）と履歴を確認する。貸出前の「申請中」「承認済み」の申請はこの画面から取り消せる。
6. 「パスワード変更」画面で、自分のパスワードをいつでも変更できる。

### 管理者

一般利用者の操作（上記）に加えて、以下を行える。

1. 「申請管理」画面で、申請中の申請を確認し、承認または却下（却下理由は必須）する。承認時には期間の重複が自動で再確認される。
2. 同画面で、承認済みの申請について備品を渡した際に貸出処理（貸出日時の記録）、貸出中の備品が返却された際に返却処理（返却日時・状態メモの記録）を行う。承認済みの申請を取り消す場合（備品故障等）は理由（必須）を入力して取消す。
3. 「期限超過一覧」画面で、返却予定日を過ぎた貸出を一覧確認する。
4. 「備品管理」画面で、備品を1点ずつ登録・編集・無効化（論理削除）・再有効化する。CSVファイルからの備品一括登録もこの画面から行う。
5. 「ユーザー管理」画面で、社員アカウントの登録・編集・無効化・再有効化、ロール（一般／管理者）の設定、パスワードの初期化を行う。ただし、最後の有効な管理者を無効化・一般ロールへ変更することはできない。
6. 「貸出履歴」画面で、全社員の貸出履歴を検索・閲覧し、CSV出力する。

# 自由記述

### 開発者向け操作

データベースマイグレーション（バックエンドコンテナ内でAlembicを実行）：

```
docker compose exec backend alembic upgrade head
```

バックエンドのテスト実行：

```
docker compose exec backend pytest
```

### 開発プロセス成果物

本プロジェクトは`hojou`運用ルールに従って開発されている。要件定義書・設計書・単体/結合テスト仕様書・作業管理・引継ぎ資料・レビュー指摘表はリポジトリ直下の各フォルダに格納されている。機能ごとの実装・設計・テストの対応状況は、`引継ぎ資料/機能別/`配下の機能別引継ぎ資料を参照のこと。
