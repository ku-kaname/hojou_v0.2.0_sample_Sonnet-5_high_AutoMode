# プロジェクト完了（v1.0.0更新） 設計書バージョン一括更新

## スコープ

[バージョン管理ルール](../../../hojou/運用ルール/開発ルール/バージョン管理ルール.md)「プロジェクト完了（初回開発、v1.0.0未到達の場合のみ）：現在のバージョンをv1.0.0にする」に従い、`設計書/`配下でv1.0.0未到達（`_v0.1.0.md`・`_v0.2.0.md`・`_v0.3.0.md`）の全ファイルをv1.0.0へリネームする。内容の変更は行わない。

- `テスト仕様書/`配下は、単体・結合テスト仕様書ともファイル名にバージョンを付与しない運用のため対象外（対象ファイルなし）。
- `要件定義書/`配下は既に全ファイルv1.0.0のため対象外（要件定義は編集禁止ルールにも抵触する）。

## アプローチ（案）

- `設計書/`配下を機械的に走査し、対象98ファイルを`git mv`でリネームする（内容変更なし）。
- リネームに伴い、`引継ぎ資料/機能別/`・`引継ぎ資料/タスク毎/`・`作業管理/タスク/`配下で、リネーム後も存在し続ける「現在の（最終確定）バージョン」をファイル名に含めて参照している箇所を、新しいファイル名に更新する。
- レビュー指摘表（ファイル名のバージョンをレビュー開始時点のまま固定する運用のため対象外）・`タスク毎`引継書および`作業管理`タスク詳細内の、レビューサイクル途中の旧バージョン（例：確定前のv0.1.0など、現在は存在しないバージョン）を指した履歴的記述は、当時の事実の記録のため変更しない。
- `backend/app/`のdocコメント中の設計書パス参照（例：`設計書：CRUD/共通/ユーザー登録_v0.1.0.md`）も同様に旧バージョンを指すことになるが、実装コードは完了済みの成果物であり、レビュー工程を経ない修正は行わない。既知の技術的負債として全体方針引継書に記録する。

## 修正対象資材

### 設計書（リネームのみ、内容変更なし）

`設計書/`配下98ファイル（`_v0.1.0.md`80件・`_v0.2.0.md`17件・`_v0.3.0.md`1件）を、全て同一フォルダ内で`_v1.0.0.md`へリネームした。対象ファイルの一覧は本PRの差分（`git log`のrename検出）を参照のこと。

### 影響資材

- `引継ぎ資料/機能別/`配下18ファイル（全体方針＋F01〜F17）：設計書への参照リンクのバージョン表記をv1.0.0へ更新。
- `引継ぎ資料/タスク毎/`配下：リネーム対象ファイルの「現在の（最終確定）バージョン」と一致する参照箇所のみバージョン表記をv1.0.0へ更新（レビューサイクル途中を指す履歴的記述は変更しない）。
- `作業管理/タスク/`配下：上記と同じ基準でバージョン表記をv1.0.0へ更新。
- `引継ぎ資料/機能別/全体方針/引継書.md`：実装コード（`backend/app/`）のdocコメントが更新対象外の設計書旧バージョンを参照し続けることを、未解決事項に追記。
