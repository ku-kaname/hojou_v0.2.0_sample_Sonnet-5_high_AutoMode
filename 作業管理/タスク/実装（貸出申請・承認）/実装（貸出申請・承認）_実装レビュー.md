# 実装レビュー

## スコープ

実装（貸出申請・承認）バックログの全成果物（`backend/app/schemas.py`・`backend/app/crud.py`・`backend/app/services.py`・`backend/app/main.py`の貸出申請・承認追加部分、`frontend/src/`配下の貸出申請・承認関連新規・修正ファイル）を対象に、`運用ルール/開発ルール/レビュー工程ルール.md`に従い実装レビュー工程を実施する。`実装_チェックリスト.md`・`FastAPI/Pydantic/SQLAlchemy/React_実装_チェックリスト.md`の各項目で確認した。

## レビュー結果

- 各チェックリストの全項目を確認した結果、指摘事項は見つからなかった。
- レビュー工程ルール「指摘が無ければレビュー指摘表の作成は不要」に基づき、レビュー指摘表は作成していない。
- `backend/app/models.py`の`LoanRequest`クラス定義（`id`・`equipment_id`・`applicant_user_id`・`start_date`・`due_date`・`purpose`・`status`・`rejection_reason`・`approved_by_user_id`・`lent_by_user_id`・`returned_by_user_id`・`cancelled_by_user_id`・`requested_at`・`decided_at`・`lent_at`・`returned_at`・`cancelled_at`・`return_note`）と、`schemas.py`・`crud.py`・`services.py`のフィールド名・使用箇所を突き合わせ、一致していることを確認した。
- レイヤー構成（main.py→services.py→crud.pyの一方向呼び出し）を全6エンドポイント（貸出申請・申請取消・承認待ち申請一覧取得・申請承認・申請却下・管理者申請取消）で確認し、違反がないことを確認した。
- 貸出申請の重複予約判定（上書き予約の防止）について、申請時点のチェック（承認済み・貸出中の申請のみ対象）と承認時点の再チェック（承認待ちの申請同士は申請時点では重複可、承認時に再度重複判定）という二段階の仕様を設計書どおりに実装できていることを、disposable SQLiteを用いたFastAPI `TestClient`による機能テストで確認した（境界値：承認済み申請と重複する新規申請は作成時点で400、承認待ち同士は作成可だが片方承認後にもう片方の承認は400、過去日開始の承認待ち申請は承認時に400）。
- 申請取消（F06）の存在漏洩防止（他人の申請を取消しようとした場合に403ではなく404「貸出申請が見つかりません」を返す設計）が実装どおりに動作することを機能テストで確認した。
- フロントエンド（`EquipmentDetailPage.tsx`への貸出申請フォーム追加、`MyRequestsPage.tsx`・`RequestManagementPage.tsx`の新規作成）について、Playwright（`frontend/node_modules`に既存インストール済み）を用いて実際にブラウザ（Chromium）を起動し、開発サーバー（バックエンド：disposable SQLiteで`uvicorn`起動、フロントエンド：`npm run dev`のVite開発サーバー）に対して以下の一連の操作を実施し、画面が設計どおりに動作することを確認した。
    - 管理者ログイン→初回パスワード変更→備品登録（検証用）
    - 備品詳細画面（`EquipmentDetailPage.tsx`）から貸出申請フォームを送信→申請結果セクションに申請IDが表示されることを確認
    - 申請管理画面（`RequestManagementPage.tsx`）の承認待ち申請一覧に新規申請が表示されることを確認→承認操作→一覧から消えることを確認
    - 自分の申請一覧画面（`MyRequestsPage.tsx`）から、承認済みとなった申請を申請IDで取消→取消結果（状態：取消済み）が表示されることを確認（自分取消は承認済み状態でも実行可能という業務仕様どおりの挙動）
    - 2件目の貸出申請を作成し、申請管理画面から却下操作（却下理由入力）→一覧から消えることを確認
    - 各操作後、通知バッジの件数が増加し、通知機能との連携が動作していることを確認
    - `console --errors`相当のブラウザコンソールエラー監視を行い、本バックログの新規コードに起因するエラーが発生していないことを確認した（既存の備品管理画面の`pattern`属性に関する1件の警告は、別バックログ（実装（備品登録管理））で作成済みの既存コードによるものであり、本バックログの対象外）
- 品質確認コマンド（`python -m ruff check app/`・`python -m mypy app/`、`npm run build`・`npm run lint`）を実行し、いずれもエラーなく完了した。
    - `ruff check app/`で検出されたFastAPI `Depends`をデフォルト引数で呼び出すB008指摘（73件）は、既存エンドポイント（ユーザー管理・備品管理等）にも同様に存在する、本プロジェクトで採用しているFastAPIの標準的な依存性注入パターンであり、新規エンドポイント（貸出申請・承認の6件）にも同じパターンで記載されているのみで、新規の問題ではないことを確認した。
    - `ruff check app/`・`mypy app/`で検出されたその他の指摘（`scheduler.py`・`database.py`・`auth.py`関連）は、いずれも本バックログの変更対象外のファイル、または本バックログより後の`実装（貸出・返却）`バックログで実装予定の日次バッチ未実装箇所に起因するものであり、本バックログの変更によるものではないことを確認した。
