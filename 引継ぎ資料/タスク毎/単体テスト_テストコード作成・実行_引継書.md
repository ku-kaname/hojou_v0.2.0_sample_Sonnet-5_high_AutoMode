    - `conftest.py`：`app.database`・`app.auth`がインポート時に参照する`DATABASE_URL`・`JWT_SECRET_KEY`の設定、および`db_session`フィクスチャを定義。
    - フロントエンドは`frontend/src/api/client.test.ts`（`isApiRowErrorList`、7ケース）を`node:test`で作成した。
    - いずれも`unit-test`スキルの「テストコードの形式」（ヘッダーブロック・項番付きコメント・`test_<メソッド名>_<項番3桁>_<内容>`命名）に従った。この命名規則はPython以外の言語にも適用されることを確認し、TypeScript側にも同じ規則を適用した。
- `単体テスト_チェックリスト.md`・`pytest_単体テスト_チェックリスト.md`（作業手順6前段）を確認し、以下の自己発見分をレビュー工程前に直接修正した。
    - `client.test.ts`のテスト名が`isApiRowErrorList_001_...`のように命名規則の`test_`プレフィックスを欠いていたため、全7箇所に付与した。
- 作業手順6（単体テストコードレビュー工程）として、`運用ルール/開発ルール/レビュー工程ルール.md`に従い、全6ファイルについて実装内容との対応・モック対象の正確性・命名規則を再確認する自己レビューを実施した。上記1件以外の不備は見つからなかったため、レビュー指摘表は作成しなかった（`レビュー指摘表_テンプレート.md`の「指摘が無ければレビュー指摘表の作成は不要」に従う）。
- 作業手順7（テスト実行）として、以下を実施し全件成功を確認した。
    - バックエンド：`uv run pytest`で55件全件成功。`uv run ruff check app/tests`・`uv run mypy app/tests`を実行し、以下2件を修正した。
        - `conftest.py`の`# noqa: E402`コメント4箇所：このプロジェクトのruff設定ではE402が無効化されているため、noqaコメント自体がRUF100（未使用）エラーとなったため削除した。
        - `conftest.py`の`db_session`フィクスチャの戻り値型：`-> Session`では`yield`を使うジェネレータ関数として不適切（mypyエラー）だったため、`from collections.abc import Generator`を追加し`-> Generator[Session]`に修正した。
    - フロントエンド：`npm test`（`node --test`）で7件全件成功。`npm run lint`・`tsc -b`を実行したところ、`tsc -b`が`node:test`・`node:assert/strict`の型解決に失敗（TS2307）した。原因は型定義パッケージ`@types/node`が`devDependencies`に存在しなかったことであり、`npm install --save-dev @types/node@22`を実行して解決した。型定義のみでランタイムコードを含まないパッケージであること、および`npm audit`で新規の脆弱性が持ち込まれていないこと（既存の4件（esbuild/vite関連moderate、react-router関連moderate+high）のみで変化なし）を確認し、「セキュリティには最大の注意を払う」という運用ルールに合致する追加と判断した。
    - 上記対応を反映し、「単体テストコード作成・実行」タスク詳細のアプローチ（案）・修正対象資材を更新した。
    - 既存コード（`backend/app/`の実装済みファイル）に対する`ruff check .`・`mypy app`の既存エラー（本タスクで作成・編集したファイル以外）は、過去の完了済みバックログの成果物であり、本タスクの範囲外として修正しなかった。
