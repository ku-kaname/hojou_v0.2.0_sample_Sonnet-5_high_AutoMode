## 進捗ログ

### 2026-10-26
**◆対応者：Sonnet 5**

- 作業手順5（テストコード作成）として、`backend/app/tests/integration/test_cross_functional_flows.py`を新規作成した（9テスト関数）。既存フィクスチャ（`db`・`client`・`make_user`・`login`・`make_loan_request`・`make_equipment`）を再利用し、各ケースは実際のHTTPエンドポイント呼び出しを順に実行して一連フローの実配線を検証する構成とした。
    - 作成直後のセルフチェック（`uv run ruff check`・`uv run ruff format --check`・`uv run mypy`）で、以下を発見・修正した（成果物の誤りではなく、作成中の自己チェックでの修正のため指摘表には記載していない）。
        - 備品無効化・再有効化エンドポイント（`/equipment/{equipment_id}/disable`・`/enable`）のパスパラメータに内部ID（`equipment.id`）を渡していたが、`main.py`のdocコメントより当該パスパラメータは資産番号（`asset_number`）を指すことが判明し、修正した。
        - ユーザー無効化エンドポイント（`/users/{user_id}/disable`）のパスパラメータも同様に、内部IDではなくユーザーID文字列を指すため修正した。
        - 未使用変数（ruff F841）を1件削除した。
        - フォーマット不一致（ruff format）2件を自動整形した。
- 作業手順6（結合テストコードレビュー工程）として、`結合テスト_チェックリスト.md`のコード側項目（テストコードの形式・フィクスチャの再利用・アサーションの網羅性等）に基づく自己レビューを実施した。この時点では指摘は検出されなかった。
- 作業手順7（テスト実行）として`uv run pytest app/tests/integration -q`を実行したところ、新規9件のうち4件が失敗した。原因を特定し、[機能横断フロー_レビュー指摘表.md](../../レビュー指摘表/結合テスト工程/機能横断/機能横断フロー_レビュー指摘表.md)に記載のうえ、テストコードを修正した。
    - No.1・No.6：返却処理エンドポイント（PUT `.../return`）呼び出し時にリクエストボディ（`json={}`）を指定しておらず、HTTP 422となっていた。`json={}`を追加して修正した。
    - No.5：ノーショー自動取消バッチの対象条件（承認済み×返却予定日過去）に対し、前提データで開始日のみを過去に設定していた（返却予定日は未来のまま）ため通知が生成されなかった。前提データの`due_date`を過去日付に修正した。
    - No.9：同一備品の期間重複制御の検証手順順序を誤り、申請者Bの重複申請作成前に申請者Aを承認済みにしていたため、Bの作成自体が拒否され「作成時は許可」の観点を検証できていなかった。手順順序を「①A作成→②B作成（両方pending）→③A承認→④B承認（拒否）」に修正した。
    - 修正後、`uv run pytest app/tests/integration -q`を再実行し、全309件（既存300件＋新規9件）成功を確認した。`uv run ruff check`・`uv run ruff format --check`・`uv run mypy`も全て通過を再確認した。
- `結合テスト（機能横断）_タスク一覧.md`の状態を更新（「テストコード作成・実行」：進行中→完了）。
