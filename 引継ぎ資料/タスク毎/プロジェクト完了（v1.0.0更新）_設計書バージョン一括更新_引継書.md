## 目的・背景

プロジェクト完了（Issue #48、PR #49、main済み）の時点で、`設計書/`配下にv1.0.0未到達（v0.1.0・v0.2.0・v0.3.0）のファイルが98件残っていた。[バージョン管理ルール](../../hojou/運用ルール/開発ルール/バージョン管理ルール.md)「v0.x.0からv1.0.0への更新は、初回開発の『プロジェクト完了（結合テストの完了後）』のタイミングでのみ行う」に従い、これらをv1.0.0へ更新する。[Issueルール](../../hojou/運用ルール/GitHubルール/Issueルール.md)「機械的な一括変更」および[作業管理ルール](../../hojou/運用ルール/作業管理ルール/作業管理ルール.md)「工程バックログの分割」の指示により、内容変更を伴う他の作業とは別のバックログ・PR（Issue #50, branch feature/50）として実施した。

## 進捗ログ

### 2026-10-26
**◆対応者：Claude Sonnet 5**

- `設計書/`・`テスト仕様書/`・`要件定義書/`配下を走査し、`_v0.1.0.md`80件・`_v0.2.0.md`17件・`_v0.3.0.md`1件（計98件、いずれも`設計書/`配下）を対象として特定した。`テスト仕様書/`配下はファイル名にバージョンを付与しない運用のため対象ファイルなし、`要件定義書/`配下は全9ファイル既にv1.0.0のため対象外と確認した。
- 対象98ファイルを、内容変更なしで`git mv`により同一フォルダ内で`_v1.0.0.md`へリネームした。
- リネームにより参照リンク・記載が影響を受ける範囲を洗い出すため、リポジトリ全体を`_v0\.[0-9]+\.[0-9]+\.md`で走査し、以下の方針で振り分けた。
    - `引継ぎ資料/機能別/`（全体方針＋F01〜F17）：機能別引継ぎ資料は常に「現在の（最終確定）状態」を記載する資料であるため、該当する全ての参照箇所（Markdownリンク・本文中のファイル名記載）をv1.0.0へ更新した（18ファイル中、該当箇所を含む全ファイルを更新し、更新後に残存する旧バージョン表記が0件であることをグレップで確認した）。
    - `引継ぎ資料/タスク毎/`・`作業管理/タスク/`：各タスクの引継書・タスク詳細は、そのタスクを実施した時点の状態を記録する資料であり、レビューサイクルを経て確定版に至るまでの中間バージョン（例：レビュー前のv0.1.0等）への言及は、当時の事実の記録として残すべきと判断した。このため、リネーム対象ファイルの「リネーム直前の実際のファイル名（＝レビューサイクルを経た最終確定バージョン）」と完全一致する記載のみをv1.0.0へ更新し、既に別バージョンへ確定済みで現在は実在しない中間バージョンへの言及（レビュー工程完了前の記述等）は変更しなかった。この基準により、`引継ぎ資料/タスク毎/`12ファイル・`作業管理/タスク/`26ファイルを更新した。
    - `レビュー指摘表/`：[バージョン管理ルール](../../hojou/運用ルール/開発ルール/バージョン管理ルール.md)「指摘表のファイル名のバージョンは、レビューを開始した時点の成果物のバージョンとし、指摘対応によるバージョンアップでは変更しない」により、ファイル名・内容とも変更しなかった。
    - `backend/app/`（services.py・schemas.py・crud.py・main.py・scheduler.py・models.py・auth.py）：docコメント中に設計書パス（例：`設計書：CRUD/共通/ユーザー登録_v0.1.0.md`）を含むが、実装はレビュー工程を完了した確定済みの成果物であり、バージョン文字列の同期のみを目的とした修正であっても、レビュー工程を経ない修正は行わないという運用（「各工程が完了したら、その成果物を勝手に修正してはいけない」）に従い、変更しなかった。既知の技術的負債として、`引継ぎ資料/機能別/全体方針/引継書.md`の未解決事項に追記した。
    - `hojou/運用ルール/開発ルール/レビュー工程ルール.md`：hojou自体（サブモジュール）のため対象外。
- リネーム後、`設計書/`配下に`_v0.`を含むファイルが残存しないこと、`引継ぎ資料/機能別/`配下に`_v0.`を含む記載が残存しないことをグレップで確認した。
