`実装（備品参照）`バックログ（Issue #20）として、F03・F04（備品検索・一覧表示、予約状況確認）の実装を行う。`設計（備品管理）`（Issue #8）の設計書に基づき、バックエンド3エンドポイント・フロントエンドのS03 備品一覧画面、S04画面のうち備品詳細・予約状況確認部分を実装する。

### 2026-10-25
**◆対応者：Claude Sonnet 5**

- `作業管理/タスク/実装（備品参照）/実装（備品参照）_タスク一覧.md`・本タスクの詳細ファイル（`実装（備品参照）_備品参照機能実装.md`）を確認した。
- 設計書（`設計書/スキーマ（schemas）/備品操作_v1.0.0.md`該当スキーマ・`設計書/サーバー処理（main）/備品管理/備品検索・一覧取得_v1.0.0.md`・`備品詳細取得_v1.0.0.md`・`備品予約状況取得_v1.0.0.md`・`設計書/CRUD/備品管理/備品一覧取得_v1.0.0.md`・`備品取得（資産番号指定）_v1.0.0.md`・`予約期間一覧取得（備品指定）_v1.0.0.md`・`貸出中申請取得（備品指定）_v1.0.0.md`）を確認し、対象エンドポイント（検索・一覧取得／詳細取得／予約状況取得の3件）と画面（S03 備品一覧、S04のうち予約状況確認部分）のスコープを確定した。
- バックエンド実装（実装スキル作業手順2）を行った。
    - `backend/app/schemas.py`：`EquipmentListItemResponse`・`ReservationPeriodResponse`の2スキーマを追加した。
    - `backend/app/crud.py`：複合クエリ結果用の内部データモデル（`@dataclass`の`EquipmentListRow`・`ReservationPeriodRow`）を追加したうえで、`get_equipments`（LEFT JOINによる貸出状況判定・動的フィルタ）・`get_equipment_by_asset_number`・`get_lending_loan_request_by_equipment`・`get_approved_or_lending_loan_requests_by_equipment`（INNER JOIN）の4関数を追加した。本バックログが、本コードベースで初めてSQLAlchemyのjoin（LEFT JOIN／INNER JOIN）を使用した。
    - `backend/app/services.py`：crud層とは項目構成が異なる内部データモデル（`@dataclass`の`ReservationPeriodRow`。借用者氏名の可視性制御のためフィールド名・設定値が変わる）を追加したうえで、`search_equipment`（一般ユーザー／管理者の有効フラグ絞り込み判定）・`get_equipment`（404判定・貸出状況算定）・`get_equipment_reservations`（404判定・借用者氏名の可視性制御）の3関数（オーケストレーション層）を追加した。
    - `backend/app/main.py`：`search_equipment_endpoint`・`get_equipment_endpoint`・`get_equipment_reservations_endpoint`の3エンドポイントを追加した。いずれも`Depends(auth.require_password_changed)`のみに依存し、管理者限定ではない（一般ユーザーも利用可能）。
    - 複合クエリの戻り値型が具体的なORMモデルに対応しない設計書上の`list`型であった点について、crud層・services層それぞれに業務コンテンツモデルとしての`@dataclass`を定義する設計判断を行った（詳細は`実装（備品参照）_備品参照機能実装.md`「アプローチ（案）」を参照）。
- フロントエンド実装（S03 備品一覧画面、S04の備品詳細・予約状況確認部分）を行った。
    - `frontend/src/types/api.ts`：`EquipmentListItemResponse`・`ReservationPeriodResponse`に対応する型（`LendingStatus`・`ReservationStatus`のユニオン型を含む）を追加した。
    - `frontend/src/api/equipment.ts`（新規作成）：`searchEquipment`（クエリパラメータを自前で構築）・`getEquipment`・`getEquipmentReservations`の3関数を実装した。
    - `frontend/src/pages/EquipmentListPage.tsx`（新規作成）：分類・キーワード検索フォーム（管理者のみ有効フラグ絞り込みを追加表示）・備品一覧表示を実装した。
    - `frontend/src/pages/EquipmentDetailPage.tsx`（新規作成）：備品詳細情報・予約状況（開始日・返却期日・状態・借用者氏名）の表示を実装した。貸出申請（F05）部分は対象外とし、別バックログ（`実装（貸出申請・承認）`）で追加する。
    - `frontend/src/App.tsx`：`/equipment`・`/equipment/:assetNumber`ルートを、一般ユーザーも利用可能な通常の`ProtectedRoute`配下（`AdminRoute`は使わない）に追加した。
    - `frontend/src/components/Layout.tsx`：ログイン済みユーザー（`user !== null`）であれば無条件に表示する「備品一覧」ナビゲーションリンクを追加した。
- 実装チェックリスト（実装全般・Python・FastAPI・Pydantic・SQLAlchemy・React）の確認を行った（実装スキル作業手順3）。
    - `uv run mypy app/`実行時、`services.py`の`search_equipment`関数内で`active_filter`変数の型推論に起因する指摘が出たため、型注釈（`active_filter: bool | None`）を明示する修正を行った（レビュー工程前のため指摘表は作成せずそのまま修正）。
- 実装レビュー工程（実装スキル作業手順4）を実施し、チェックリスト全項目で指摘事項は見つからなかった（詳細は`実装（備品参照）_実装レビュー.md`を参照）。
- 品質確認コマンドを実行し、いずれもエラーなく完了した：バックエンドは`uv run ruff check app/`・`uv run mypy app/`、フロントエンドは`npm run build`・`npm run lint`。
